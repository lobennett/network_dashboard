Set up your computer

Connect the dashboard to your own copy of the study on Oak. Complete the setup once, then start the local service whenever you want to review data.

Before you begin: you need a Sherlock account with Stanford authentication and read access to the lab’s russpold Oak partition. Ask the study owner to arrange access if you do not have it.

Run the commands below in Terminal on your own computer, using bash or zsh. Copy buttons copy commands only; they do not run them.

1. Install the prerequisites

You need What it does
Git + git-annex Track dataset versions and retrieve large study files.
SSH + SCP Authenticate to Sherlock and transfer files. Included with macOS; install OpenSSH on Linux.
uv + Python 3.12+ Install and run the local service. uv can install Python for you.
DataLad Install study subdatasets and fetch their files. Install separately from git-annex.
Current Chrome Open the dashboard and grant local-network/loopback access.

Processing runs on Sherlock. Allow space for the images you fetch; the example below downloads one BOLD file of about 133 MB.

Choose your operating system

macOS

Install Homebrew if needed, follow its PATH instructions, then run: 

brew install git git-annex uv
Ubuntu / Debian Linux 
sudo apt update
sudo apt install git git-annex openssh-client curl
curl -LsSf https://astral.sh/uv/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"

Windows: use Ubuntu in WSL2 and run the Linux commands there. This setup has been tested on macOS; WSL2 browser connectivity has not yet been verified.

Install Python and DataLad

uv python install 3.12
uv tool install --python 3.12 datalad
uv tool update-shell
export PATH="$HOME/.local/bin:$PATH"

Check that these commands print version numbers or a Python path before continuing: 

git --version
git annex version
ssh -V
uv --version
uv python find 3.12
datalad --version

Installation references: uv · DataLad · git-annex on macOS.

2. Install the dashboard service

This installs the small Python service that reads your local study files. The website already provides the interface. 

uv tool install --python 3.12 DASHBOARD_ORIGIN/downloads/network_dashboard-0.1.0-py3-none-any.whl
network-dashboard --help

3. Connect to Sherlock

Open your SSH configuration in a terminal editor:

mkdir -p ~/.ssh
chmod 700 ~/.ssh
nano ~/.ssh/config

Paste this block into that file, replacing YOUR_SUNET_ID with your own username. If a Host sherlock entry already exists, update it instead of adding a duplicate. In nano, save with Ctrl+O, Enter, then exit with Ctrl+X. 

Host sherlock
  HostName login.sherlock.stanford.edu
  User YOUR_SUNET_ID
  ControlMaster auto
  ControlPath ~/.ssh/sherlock-%C
  ControlPersist 10m

Run this check and complete Stanford authentication. It runs one check on Sherlock and returns you to your local terminal. Expect Oak access confirmed: 

ssh sherlock 'test -r /oak/stanford/groups/russpold/data/network_grant/network-dashboard-cache/records.sqlite && echo "Oak access confirmed"'

4. Get the pilot study

These commands create ~/network-review, clone the study metadata, and copy the dashboard index. Run the clone once; if you already have this clone, use the next block. 

mkdir -p ~/network-review
cd ~/network-review
export DATALAD_SSH_MULTIPLEX__CONNECTIONS=false
git clone ssh://sherlock/oak/stanford/groups/russpold/data/network_grant/network-study-pilot-s03 study
scp sherlock:/oak/stanford/groups/russpold/data/network_grant/network-dashboard-cache/records.sqlite records.sqlite

Install the raw-data subdataset and fetch one image to try in NiiVue: 

cd ~/network-review/study
export DATALAD_SSH_MULTIPLEX__CONNECTIONS=false
datalad get -n sourcedata/raw
cd sourcedata/raw
git config remote.origin.annex-shell /scratch/users/logben/mechababs-work/campaign-base/bin/git-annex-shell
git config remote.origin.annex-ignore false
datalad get sub-s03/ses-07/func/sub-s03_ses-07_task-goNogo_run-1_echo-2_bold.nii.gz

The explicit annex-shell path uses the modern git-annex installed on Sherlock. It must be accessible to your account. Only requested files are downloaded; MRIQC reports and other images need separate retrieval.

5. Start reviewing

cd ~/network-review
export DATALAD_SSH_MULTIPLEX__CONNECTIONS=false
network-dashboard --study study --index records.sqlite \
  --allow-origin DASHBOARD_ORIGIN

Leave this terminal running. Open the dashboard, click Connect to local study, and allow local-network/loopback access when Chrome asks. Select sub-s03 → MRIQC → ses-07 / goNogo → View echo-2 in NiiVue.

Next time, repeat this step only. Press Ctrl+C in the terminal to stop the service. Reauthenticate to Sherlock before fetching more files if your SSH session has expired.

Fetching more files and refreshing the snapshot

In a second local terminal, install the relevant subdataset with datalad get -n and configure its remote annex-shell as in step 4. Then retrieve files with DataLad or fetch one indexed artifact by its ID from Files & provenance: 

cd ~/network-review
export DATALAD_SSH_MULTIPLEX__CONNECTIONS=false
network-dashboard --study study --index records.sqlite --get-artifact ARTIFACT_ID

Replace ARTIFACT_ID before running. Anatomical previews require recorded defacing evidence. The website does not automatically download missing files.

The header shows the index timestamp. To refresh, update the study and relevant subdatasets from Oak, copy a newly rebuilt index using the SCP command in step 4, then reload the dashboard.

Troubleshooting
  • Command not found: reopen Terminal after installation, then rerun the prerequisite checks. For uv tools, run uv tool update-shell.
  • Permission denied / no Oak confirmation: check your SSH username, complete Stanford authentication, and confirm russpold Oak access with the study owner.
  • Cannot load the study: keep the service running, use the same dashboard address as the launch command, and allow local-network/loopback access in Chrome’s site settings.
  • Image unavailable: fetch that file and install its subdataset first. The example only retrieves one echo-2 image.
  • Address already in use: a service may already be running on port 18782. Use that terminal or stop it with Ctrl+C before starting another.

Study data travels directly from your local service to your browser. Vercel hosts only the interface; your SSH credentials stay on your computer.
