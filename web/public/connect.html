Connect your study

You need a Sherlock account with russpold Oak access, Python 3.12+, uv, DataLad, and git-annex on your computer. The shared website contains only the interface. Study files are retrieved over your own SSH connection and served locally.

1. Install the local service

Download the backend package, then install it: 

uv tool install ~/Downloads/network_dashboard-0.1.0-py3-none-any.whl

2. Authenticate and clone the study

Configure a sherlock alias in ~/.ssh/config using your own username. Complete Stanford authentication through SSH; never enter credentials into this website. 

Host sherlock
  HostName login.sherlock.stanford.edu
  User YOUR_SUNET_ID
  ControlMaster auto
  ControlPath ~/.ssh/sherlock-%C
  ControlPersist 10m
ssh sherlock
# After authenticating, exit back to your computer.
export DATALAD_SSH_MULTIPLEX__CONNECTIONS=false
git clone ssh://sherlock/oak/stanford/groups/russpold/data/network_grant/network-study-pilot-s03 study
scp sherlock:/oak/stanford/groups/russpold/data/network_grant/network-dashboard-cache/records.sqlite .
cd study
datalad get -n sourcedata/raw
cd sourcedata/raw
git config remote.origin.annex-shell /scratch/users/logben/mechababs-work/campaign-base/bin/git-annex-shell
git config remote.origin.annex-ignore false
# Fetch the functional scans you want to review (or one filename).
datalad get sub-s03/ses-07/func
cd ../../..

This is the current sub-s03 pilot snapshot. Only requested annex content is downloaded. The remote annex-shell path selects the installed modern git-annex; it must remain accessible to your account.

3. Start and connect

From the directory containing study/ and records.sqlite: 

network-dashboard --study study --index records.sqlite \
  --allow-origin DASHBOARD_ORIGIN

Leave this terminal running, return to the dashboard, and click Connect to local study. Allow local-network access when the browser asks. Current Chrome is recommended. The service listens only on 127.0.0.1:18782 and permits this exact website origin.

Missing files are fetched explicitly with DataLad. To fetch one indexed artifact and verify its checksum, use: 

network-dashboard --study study --index records.sqlite --get-artifact ARTIFACT_ID

For MRIQC and other derivatives, install the corresponding study subdataset first with datalad get -n derivatives/NAME, then configure its remote.origin.annex-shell and remote.origin.annex-ignore as above. Anatomical previews require recorded defacing evidence.

To refresh, update the study and relevant subdatasets from Oak, copy a newly rebuilt index, then reload. The timestamp in the dashboard identifies the snapshot; an open page does not imply live job status.
